# Shadowrocket + RoscomVPN routing — дизайн

Дата: 2026-09-11

## Цель

Получить конфиг Shadowrocket, который воспроизводит маршрутизацию
[RoscomVPN](https://github.com/hydraponique/roscomvpn-routing) (профиль DEFAULT,
а также WHITELIST), остаётся коротким и обновляется вместе с апстримом
без ручной работы.

## Ограничения, выясненные при исследовании

| Факт | Следствие |
|---|---|
| RoscomVPN публикует правила как `geosite.dat`/`geoip.dat`, `.mrs` (Mihomo), `.srs` (sing-box) | Shadowrocket ни один из этих форматов не читает |
| Исходники доменных списков лежат в ветке `master` репозитория `roscomvpn-geosite`, папка `data/`, формат v2fly (`domain:`, `full:`, `keyword:`, `regexp:`, голые строки) | Формат текстовый, конвертируется в Surge-style `.list` построчно |
| IP-списки публикуются текстом: `roscomvpn-geoip`, ветка `release`, `text/{direct,whitelist,private}.txt` (голые CIDR, ~36 000 строк в `direct`) | Пригодны для `RULE-SET` после добавления префикса `IP-CIDR,` |
| Shadowrocket `RULE-SET` читает Surge-списки (`ТИП,значение` на строку), `DOMAIN-SET` — голые домены; регулярок по домену нет, есть только `DOMAIN-WILDCARD` (с версии 2.2.65) | `regexp:` переводим в `DOMAIN-KEYWORD` по буквальному префиксу либо выбрасываем |
| Кастомная GeoIP-база (mmdb) задаётся только в настройках приложения, не в конфиге | Вариант с mmdb требует ручного шага и подменяет встроенную базу |
| Списки `custom-category` (games, ru-apps) построены на `PROCESS-NAME` | На iOS неприменимы, не переносятся |
| Пользователь требует маленький конфиг | Все домены/IP выносятся в внешние rule-set'ы, конфиг содержит только ссылки |

## Рассмотренные подходы

1. **Ссылаться на файлы RoscomVPN напрямую из конфига.** Работает только для IP-списков
   (`text/*.txt`); доменные списки в v2fly-формате Shadowrocket не поймёт. Отвергнут.
2. **Вписать все правила в конфиг.** ~2 500 доменных правил плюс 36 000 CIDR: конфиг на
   мегабайт, противоречит требованию. Отвергнут.
3. **Собственный репозиторий с конвертером и GitHub Actions** (выбран). Скрипт переводит
   списки в `.list`, workflow запускает его ежедневно, конфиг ссылается на `.list` по URL.
   Так устроены все живые российские конфиги для Shadowrocket (misha-tgshv, zeklop,
   tatarinovms).
4. **Кастомная mmdb вместо IP-списка.** Возможна поверх подхода 3 (инструмент
   Loyalsoldier/geoip умеет собирать mmdb из текстовых списков), но требует ручной
   настройки в приложении и подменяет встроенную базу. Оставлен как опция на будущее.

## Архитектура

```
roscomvpn-geosite (master, data/*)  ─┐
                                      ├─> build.py ─> rules/*.list ─┐
roscomvpn-geoip (release, text/*.txt) ┘        │                    ├─> Shadowrocket (RULE-SET по URL)
                                               └─> roscomvpn.conf ──┘
                                                   roscomvpn-whitelist.conf
GitHub Actions: cron ежедневно после сборки geoip (03:10 UTC) + ручной запуск + push
```

### Компоненты

- `build.py` — конвертер и сборщик, только стандартная библиотека Python 3.9+.
  Функции: загрузка исходников (сеть или `--src-dir`), конвертация строк geosite и geoip,
  дедупликация, запись списков «только при изменении», рендер шаблонов конфигов,
  валидация результата. Режим `--check` валидирует уже собранное без сети.
- `templates/*.conf.tmpl` — шаблоны конфигов с плейсхолдерами `{BASE_URL}`, `{BUILD_DATE}`.
- `rules/*.list` — сгенерированные rule-set'ы (коммитятся в репозиторий).
- `.github/workflows/update.yml` — сборка, тесты, коммит при изменениях.
- `tests/test_build.py` — unittest для конвертера, валидатора и сборки на фикстурах.

### Соответствие правил

Порядок повторяет `MIHOMO/default.yaml` RoscomVPN: private → блок QUIC → BLOCK →
torrent → PROXY (google-play, twitch-ads, youtube, telegram, github) → DIRECT (игры,
twitch, microsoft, apple, pinterest, category-ru, whitelist) → geoip:direct → FINAL PROXY.

Отличия от оригинала и их причины:

- IPv6 выключен (`ipv6 = false`) вместо правила `IP-CIDR,::/0,REJECT-DROP`: geoip RoscomVPN
  только IPv4, а выключенный IPv6 в Shadowrocket не заставляет приложения ждать таймаута.
- `REJECT` вместо `REJECT-DROP` для рекламы и телеметрии: мгновенный отказ вместо зависания.
- `regexp:` → `DOMAIN-KEYWORD` по буквальному префиксу (2 записи в используемых списках).
- Правила по имени процесса не переносятся (нет на iOS).
- Torrent: в DEFAULT — DIRECT (как в Mihomo-конфиге), в WHITELIST — REJECT (как в HAPP).

### DNS

Как у RoscomVPN: Яндекс `https://77.88.8.8/dns-query` и Google `https://8.8.8.8/dns-query`
параллельно для прямых доменов; резерв — обычный DNS Яндекса, Google через прокси,
системный. Все четыре адреса проверены реальным DoH-запросом при проектировании.

### Обработка ошибок

- Сеть: 3 попытки с паузой; при провале сборка падает, старые файлы не трогаются.
- Пустой результат конвертации при непустом источнике — ошибка сборки (защита от смены
  формата апстрима).
- Невалидные строки (запятые, пробелы, недопустимые символы) пропускаются и считаются.
- Валидатор конфига проверяет, что каждый `RULE-SET` ссылается на существующий список,
  типы правил известны, `FINAL` стоит последним.
- Workflow коммитит только при изменениях, сообщение с `[skip ci]` — цикла не будет.

### Тестирование

- Юнит-тесты конвертера (все типы записей, комментарии, атрибуты, регулярки, include,
  CIDR v4/v6, дедупликация).
- Тест «запись только при изменении».
- Тест валидатора (ссылка на отсутствующий список, `FINAL` не последний).
- Сквозная сборка на фикстурах во временной папке.
- Реальная сборка из сети при разработке: проверка количества правил в каждом списке.
